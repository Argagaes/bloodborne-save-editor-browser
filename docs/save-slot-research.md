# Character slot research

Three supplied character files, `userdata0003` through `userdata0005`, contain valid characters, but have different variable-length equipment sections. After aligning their character fields using `FACE`, no byte in the aligned character section follows the corresponding 3/4/5 or 2/3/4 slot numbers. This does not rule out a different encoding or other slot-dependent data.

The separate `userdata0010` system file appears to hold the character selection list. Another editor documents a ten-slot table at 0x1096 with 0x192-byte records: https://github.com/SrShadowy/BBSaverEditor. This independently supports the report that copying and renaming a character file is insufficient to add a character to the in-game list. That external description alone does not establish how to create or duplicate an entry safely, which fields identify the character or slot, or whether other system fields must change.

The supplied system snapshots before and after creating slot 6 show a ten-byte occupied array at `0x108c`: byte `0x1092` changes from 0 to 1 for slot 6. Its 402-byte summary at `0x1096 + 6 * 0x192` gains the new character's name and other details. The last-selected slot at `0x89c` also changes, an existing character's playtime changes, and large unrelated system regions differ. The evidence does not establish whether the last-selected field is needed for recognition; the experimental copy leaves it unchanged.

The experimental copy function duplicates the existing source summary, marks the destination occupied, and exports the character and system file with matching backup names. It checks that the source summary name matches the opened original character and only allows an empty destination. This comparison is not a unique identity check. Summary details can remain stale until the game updates them. Loading a copied slot in-game and checking both characters remain intact is still required; the snapshot comparison alone does not prove all slot-related state has been found. Preserve the entire original save directory and avoid writing the live save while the game is running.
