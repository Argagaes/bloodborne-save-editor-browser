# Shortcut flag investigation

Enhanced `emevd_patches.json` event 12102210 implements Activate All Shortcuts. The extracted `lamp-test/shortcut-mod-flags.json` records 84 flag writes to 83 distinct flags, excluding mod-control flags; 19 writes clear flags rather than setting them. The instructions include a three-flag batch. The mod describes its scope as almost all locked doors and elevators. One logical shortcut may involve multiple flags, and complementing all open values does not establish a safe original locked state.

The installed game's MSBB map files include object interactions, their flag IDs, entity IDs, names and positions. These can help identify individual shortcuts, but not every event flag directly equals an object-interaction flag. The Yharnam Together door-flag inventory likewise includes interaction, event completion and related flags; it is not automatically a named list of shortcuts.

A controlled Enhanced shortcut-on save compared with lamp-test/new-base is needed to locate the mod's effects in the serialized save. Existing lamp findings establish the bit ordering, but they do not prove that different thousand-flag groups are contiguous in the save. Do not use the lamp group's offset as if it established the position of every shortcut flag. The comparison can identify a batch and suggest serialization offsets, but unlocking and especially relocking individual doors and elevators must be validated on disposable saves before offering them as verified controls.

## All-shortcuts comparison

The controlled `new-base` and `all-shortcuts` saves share the same hunter. Comparing relative to each save's independently found flag base shows 50 changed bytes in the first 150,000 bytes. Matching the mod's bit operations found strong unique group matches, including 12410 at flag base + 7252, 62411 at +27377, 12400 at +7127, 12420 at +7377, 12500 at +7502, 12601 at +22002, 12700 at +7752, 12800 at +7877, 13200 at +8127, 13300 at +8252, 13401 at +22752, 13501 at +22877, 13601 at +23002, and 62420 at +13127. Some groups have ambiguous matches or only one changed bit. These are inferred positions, not yet in-game verified.

The map's object-action name describes entity 12410202 as a main-street lever at approximately (-200.97, -44.26, 90.88). Event flag 12410202 corresponds under this mapping to flag base +7277 mask 0x20, and changed from off to on in the mod comparison. `lamp-test/shortcut-main-street/userdata0001` sets only that bit on the baseline for a controlled test. It may not be sufficient for that shortcut, and the map-object label and player-facing description need confirmation. Setting this one bit alone does not establish that clearing it will reliably re-lock the gate or that elevator flags are reversible.

The user confirms `shortcut-main-street` opens the main-street gate. This validates setting flag base +7277 mask 0x20 (event flag 12410202) in their setup. `shortcut-main-street-lock` starts from all-shortcuts and clears only that bit; this tests the reverse operation while the other shortcut flags remain in their mod-open state. Relocking remains unverified until tested.

The user confirmed clearing flag base +7277 mask 0x20 locks the main-street gate again. This shortcut is now available as a checkbox in the final editor. `shortcut-central-batch` starts from the verified gate-open baseline, sets m24_01 flags 12410200 and 12410203 and object-action flags 62411303 and 62411306, and enables the Central Yharnam lamp for travel. The first two map object labels are courtyard and second shortcut; the latter two are doors in the dark house. The four other shortcuts have not been isolated or verified, and no all-shortcuts switch is offered yet.

User supplied `lamp-test/new-base/centralyharnam/userdata0001` with the character in m24_01. All four candidate bits in the earlier batch are already on in this baseline. Four individually positioned test copies under `lamp-test/shortcut-position-tests` therefore clear one candidate bit apiece and place the character at the corresponding object origin +1.5 vertical units, using the final editor's existing coordinate operation. The baseline file is untouched. The manifest identifies the inferred flags, bit masks and object positions. An unchanged open state does not disprove the mapping if other flags or map load behavior interfere; if an interaction stays open, compare with baseline and report the observed location and state.

The user identified the positioned tests: #1 is the gate/lever opening a door next to Iosefka's Clinic; #2 is the gate/lever near the girl who gives the Tiny Music Box; #3 is a dark-house door leading toward the Great Bridge boss; #4 is the other door in that same house. These descriptions identify nearby objects, but the observed locked/open states have not yet been reported. Because all four candidate bits were already set in the baseline, each numbered save clears only its corresponding candidate bit.

The user reports all four numbered positioned tests were locked. Clearing each candidate bit is therefore sufficient to produce the locked state in those copies. `shortcut-position-open` contains matching positioned saves with the respective bit set again; each differs from its locked counterpart at exactly one byte. These test whether setting the bit alone reopens each shortcut before it is offered as a toggle.


The user reports all four matching `shortcut-position-open` saves show the corresponding shortcuts open, while each cleared-bit save showed it locked. All four were added to the final editor alongside the previously verified main-street gate. Area and all-listed checkboxes affect only these five verified shortcuts; other game shortcuts remain unmapped.


## Expanded map catalog

The final editor now contains 65 positive shortcut-related flag entries in 14 map groups. Their offsets are inferred from the all-shortcuts save comparison; only the five listed above were tested individually. Eleven persistent flag-clear operations from Enhanced are handled by the global on control, and global off restores those auxiliary bits from the file originally opened in the current session. Seven map-visit or otherwise unresolved clear operations are omitted. The control therefore cannot claim to reproduce every operation or reliably lock every real shortcut. Game MSB object-action and EMEVD references provide internal names and candidate positions. Twelve entries have no known position; twelve link to multiple positions, which may be candidates rather than proven shared controls. Imported Yharnam Together map images remain local to the browser session.
